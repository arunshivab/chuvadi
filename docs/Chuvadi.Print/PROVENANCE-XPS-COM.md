  package `mingw-w64-common` 11.0.1 (`/usr/share/mingw-w64/include/`). What the package says about their licence:
  - `prntvpt.h` states it outright: "This file has no copyright assigned and is placed in the Public Domain".
  - The other five are generated by WIDL from `.idl` sources, which are not in the package, and carry no licence
    line of their own.
  - The package's copyright file lists `mingw-w64-headers/include/*` as public domain, with named LGPL exceptions.

  - I could not check the `.idl` sources themselves. What we took from all six headers is interface facts (slot order,

  interface's methods (its vtable), each method's parameters, and the GUIDs.

## Design choices that follow from the API

- `IPrintDocumentPackageTarget::GetPackageTarget` returns only an `IXpsDocumentPackageTarget`, so a package reaches
  the queue through the XPS Object Model. The flow (approved as route A, D-238):
  1. Our `XpsWriter` package is loaded with `CreatePackageFromStream`.
  2. Each document is started with `StartNewDocument`.
  3. Each page is sent with `AddPage`.
  4. `Close` ends the package.
- The job PrintTicket comes from the same driver-merged DEVMODE `WindowsPrinterTarget` uses, converted at job scope.
- The whole submission runs on one thread of its own in the multithreaded apartment. This keeps the
  PrintTicket provider on one thread, and status callbacks need no message loop.
- Status arrives through the job object's connection point for `IPrintDocumentPackageStatusEvent`. The sink
  answers the vtable call. It does not implement IDispatch late binding (`Invoke` returns E_NOTIMPL).

## Open points, settled by the Windows run (WINDOWS-VERIFICATION D4)

1. **Status events.** Microsoft's pages do not say how the status sink is registered. We use the connection
   point on the job object. Step 11i records whether status arrives:
   - **Connected, with a `Completed` status:** this works as built.
   - **"Status events not connected":** the job still counts as printed once the queue takes every page.
   - **"None received":** the print system may call through IDispatch. A follow-up then decides what to do.
2. **`jobOutputStream` = NULL** sends the job to the queue's port. The documentation does not state this. Steps
   11i and 11j show it: the output lands in the port file.
3. **`discardControlPartName` = NULL** for `GetXpsOMPackageWriter`. Also not documented; steps 11i and 11j show it.
