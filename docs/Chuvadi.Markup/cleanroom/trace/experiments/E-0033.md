# E-0033: Chunked child storage (patch 11, D-330, D-331)

- Hypothesis: with the given MarkdownNode storing more than 8,192 children in chunks, the 2 MiB and 4 MiB figures fall to a few bytes alive per input char, provided no pass of mine turns the chunks back into one list. Revision 8 does that in the span walk after the inline phase (R-MD-0275 read the document's children through MutableChildren).
- Cases: gate run (every output, the D-309 span check and the new D-331 storage check with a document of 20,000 paragraphs); gate mem at 512 KiB, 1, 2 and 4 MiB.
- Command: gate run --phase P4; gate mem, run alternately on revision 8 (with patch 11's library and gate laid over it) and revision 9, twice each.
- Before (revision 8 with patch 11, this machine, 2 cores; two runs):
  - 512 KiB: 43.9 and 44.4 M chars/s, 27.0 bytes allocated per char, 0 gen2 GC per round, 2.0 MiB alive at a GC
  - 1 MiB: 33.4 and 35.3 M chars/s, 26.9 bytes per char, 0 gen2, 4.3 MiB alive
  - 2 MiB: 26.1 and 21.6 M chars/s, 26.7 bytes per char, 0 gen2, 77.5 MiB alive
  - 4 MiB: 25.9 and 24.1 M chars/s, 26.7 bytes per char, 0 gen2, 82.1 MiB alive
  - storage check: not passed (the document's children are a list again after the parse)
- First try: every read moved onto Children. The 2 and 4 MiB figures fell to 8.2 and 13.0 MiB alive, but allocation rose to 27.3 bytes per char: foreach over the IReadOnlyList interface boxes an enumerator for every node. The loops now go by index.
- After (revision 9, R-MD-0280; two runs):
  - 512 KiB: 51.6 and 49.9 M chars/s, 27.0 bytes per char, 0 gen2, 2.0 MiB alive
  - 1 MiB: 38.3 and 40.3 M chars/s, 26.9 bytes per char, 0 gen2, 4.3 MiB alive
  - 2 MiB: 33.3 and 37.1 M chars/s, 26.7 bytes per char, 0 gen2, 8.7 MiB alive (4.2 bytes per input char)
  - 4 MiB: 32.0 and 31.9 M chars/s, 26.6 bytes per char, 0 gen2, 13.5 MiB alive (3.2 bytes per input char)
  - storage check: passed
- This machine showed no gen2 collection per round for either revision (the reference machine showed 1 for revision 8 at 2 and 4 MiB). No size is slower than revision 8. Output unchanged (full gate).
- Conclusion: R-MD-0280.
