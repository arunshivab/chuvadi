# Chuvadi.Docs — Changelog

## 1.5.1 (2026-10-28)

Source compatibility fix (D-38: no source breaks in minor versions).

- `DocxTemplate.Fill(input, output, null)` compiles again and binds to the text-values overload, as before 1.5.0 (the `TemplateData` overloads made a bare `null` ambiguous). The pre-existing overload carries `[OverloadResolutionPriority(1)]`.
- The same applies to the other overload sets added in 1.5.0: `GetPlaceholders(null)` and `CheckTemplate(null)` bind to the path overloads, `TemplateData.Set(key, null)` sets an empty text value, and `SetItems(name, null)` binds to the item overload (both throw or behave as documented instead of failing to compile). Overload sets from 1.3–1.4 (`NumberingCollection.Contains` / `Remove`) were new together and have no earlier calls to break; `Document.Load`, `DocxReader.Open`, `SaveTo` and `AddParagraph` are unchanged since 1.1.
- A compile-guard test keeps these calls as written.

## 1.5.0 (2026-10-28)

Exact image anchoring (pictures as runs with their full geometry, read back by Document.Load), template blocks (repeating rows and blocks, conditions, nested data, formatted values), and the loader additions a paginator needs (hyperlink targets, positional tabs, stated page size, default tab stop).

### Images: exact anchoring (6b)

- **Document.Load reads pictures into the paragraph model**: each DrawingML picture becomes an image `Run` (`Run.Image`) at its exact place — inline in the text flow, or floating on its anchor paragraph — in the body, tables, nested tables, headers and footers. Previously loaded documents dropped their pictures on save (only `Document.Images` listed them). Load → save reproduces document.xml and headers exactly for files written by Chuvadi.Docs.
- **Full anchor geometry** on `FloatingPosition`: per-side distances from text (`DistanceTopPt` … , `EffectiveDistances`), wrap side (`WrapSide`: both, left, right, largest), wrap outline (`WrapPolygon`, edited flag), layout in table cell, simple absolute position (`UseSimplePosition`, `SimplePositionXPt/YPt`), plus the existing anchors, offsets, alignments, wrap type, behind/in front, z-order (`RelativeHeight`), lock and overlap.
- **Picture properties** on `ImageSpec`: `Crop` (`ImageCrop`, a:srcRect), `RotationDegrees`, `FlipHorizontal`, `FlipVertical`, `EffectExtent`, `InlineDistance`, `Name`, `Title`, `Hidden` — written and read back.
- **`Document.GetImagePlacements()`**: every picture with its paragraph (the anchor for floating pictures), run and run index, host (body/header/footer), section, header/footer object and table cell — what a paginator needs to place each image; use `GetEffectiveParagraphFormat` for the anchor paragraph.
- One parser and writer for pictures everywhere (`Document.SaveTo`, `Document.Load`, `DocxTemplate`, `DocxReader.Images()`): `ImageInfo` gains `Crop`, `RotationDegrees`, flips and `EffectExtent`, and its `Position` now carries the full geometry; template image placeholders write crop/rotation/wrap details too.
- **Percentage positions and sizes** (Word 2010+): `FloatingPosition.HorizontalOffsetPercent` / `VerticalOffsetPercent` (wp14:pctPosHOffset/V) and `ImageSpec.RelativeWidth` / `RelativeHeight` (`RelativeSize`: percent of page/margin frames, wp14:sizeRelH/V) are read and written back as Word writes them — mc:AlternateContent with a wp14 Choice and an absolute Fallback.
- **Linked pictures**: `ImageSpec.LinkUrl` (a:blip/@r:link with an external relationship) — a linked-only picture keeps its place and size with empty `Bytes`; "link and save" keeps both. Media in formats the library does not recognise (WebP is now recognised) are kept as opaque bytes instead of being dropped.
- **Markup compatibility**: run-level mc:AlternateContent takes the first Choice whose `Requires` namespaces are understood, else the Fallback.
- Only a drawing's own properties are read: a text box or group that contains a picture keeps its text and is not mistaken for that picture. Drawings that are not pictures (charts, SmartArt, shapes, groups, text boxes) keep their text as before (they are not image runs and are not written back); `DocxReader.Images()` still lists the first picture of a group or text box.
- `behindDoc` is kept for every wrap type (it was written only with Wrap None).
- Hostile values are clamped on load (negative sizes and distances, crops leaving nothing visible, huge polygons, stray elements inside position values); a picture whose media is missing is skipped. `DocxReader.Images()` (and so `Document.Images`) reads each media part once however many drawings show it.
- `Document.SaveTo(path)` writes to a temporary file beside the target and replaces the target only when the save succeeds — a failing save no longer leaves a truncated file or destroys the file being overwritten.
- Behaviour notes: the same picture bytes used several times are now stored as one media part (smaller files; document.xml unchanged); a loaded picture's default name ("Picture N") is renumbered on save; VML pictures (`w:pict`, Word 2003 style) still load as text only.
### Templates

- **Template data model**: `TemplateData` — text values, formatted values (`TemplateValue`: runs layered over the placeholder's formatting), images, flags, nested objects (`{{Customer.Name}}`), repeating collections (`AddItem`, `SetItems`, plain-value lists as `{{.}}`); lookups fall back to the enclosing scope. `TemplateData.From(textValues, imageValues)` adapts the classic dictionaries.
- **Repeats**: `{{#Items}}` … `{{/Items}}` expands table rows (markers in one row or across a group of rows), paragraph/table blocks (markers in their own paragraphs; a marker paragraph with other text keeps it), or run text inside one paragraph — nested to any depth with item scopes.
- **Conditions**: `{{?Flag}}` … `{{/Flag}}` and the inverse `{{^Flag}}` … `{{/Flag}}`, in the same three placements; truthy = true, non-empty text, a non-empty list, an object or an image. `{{#Obj}}` enters an object's scope.
- **Formatted values and per-item images**: a `TemplateValue` keeps the placeholder's font and size under the value's own bold/colour…; images set on items become one picture per repeated row.
- **Strict mode** (`TemplateOptions.Strict`): every missing value, marker without a partner or markers that cannot form a block are reported together in one `DocxTemplateException` and no output is written. Non-strict: `MissingValue = LeaveTag` (default, as before) or `Empty`.
- **Placeholder listing**: `DocxTemplate.GetPlaceholders(path | stream)` — name, kind (value, repeat, condition, inverted condition), enclosing blocks, part (body, headers, footers, notes) and block scope (inline, blocks, table rows).
- **Streams**: `DocxTemplate.Fill(Stream template, Stream output, TemplateData, TemplateOptions?, CancellationToken)` (non-seekable input buffered within the limits; both streams left open) and `Fill(path, path, TemplateData, …)`. `TemplateOptions` carries the template password, output encryption, read limits, `MaxBlockDepth` (32) and `MaxGeneratedItems` (1,000,000).
- **Split placeholders keep formatting**: a placeholder Word split across runs is gathered into its first run; the other runs of the paragraph keep their text and formatting (previously the whole paragraph was merged into its first run). Image placeholders no longer flatten their paragraph either.
- **Each repetition is expanded and filled on its own** and never read again: a value that looks like a placeholder or a block marker (e.g. text "{{Secret}}" typed by a user) stays literal at every level. Lookups follow the template's nesting first (innermost item outwards), then the data's own parents, so a list shared by several items sees each enclosing item; a missing value inside a repeat follows `MissingValue` / `Strict` directly (each problem reported once).
- **Rows in content controls**: repeat markers in table rows wrapped in `w:sdt` or `w:customXml` (both rows in one control, each in its own, or one wrapped and one plain) repeat the rows; later copies drop the optional content-control id. A one-cell row whose content is exactly a block (`{{#Items}}{{.}}{{/Items}}`, nothing else in the row) repeats the row (it was inline). A block can only clone or remove content inside the repetition being expanded. Block markers in other places (e.g. one in a table cell, the other outside the table) do not form a block, and when a block cannot form, the blocks inside it are still expanded.
- **Valid output after removal**: a cell, header, footer, note, text box or body left without a paragraph gets an empty one (a cell always ends with a paragraph); a table whose rows were all removed is removed.
- **Unique ids**: repeated content gets new drawing ids (wp:docPr), bookmarks with new ids and names (a bookmark half outside the repetition is dropped) and no duplicate Word paragraph ids; image relationship ids and drawing ids never clash with ids already in the package, also when an output is filled again as a template. The same image bytes are stored once.
- **Formatted values keep the placeholder's run properties** that Docs does not model (w14 effects, emphasis marks, revision marks…), in schema order; only the properties the value sets are replaced (fonts and language merge attribute by attribute). Line breaks in a value survive when an image placeholder before it splits the same text.
- **`DocxTemplate.CheckTemplate(path | stream)`** lists the problems a fill would meet whatever the data (unpaired markers, markers that cannot form a block). `GetPlaceholders` lists in document order.
- `TemplateData` refuses circular data (an object or item that is the data itself or an enclosing scope). `TemplateOptions` are validated, and `MaxGeneratedElements` (50,000,000 XML nodes) bounds repetition alongside `MaxGeneratedItems`; fills observe cancellation throughout.
- Hostile templates: placeholder scanning is linear (an unterminated `{{` followed by thousands of spaces no longer stalls), and markers nested in text can no longer exhaust the stack: at most `MaxBlockDepth` (64 to 1,024) block markers stay open at a time, older pending ones are left as text (reported as without a partner), and a fill still stops with `DocxTemplateException` beyond `MaxBlockDepth`. A value containing a character XML cannot hold (e.g. U+000B) is reported as a problem.
- Marker paragraphs are removed only when nothing else is in them: page and column breaks, symbols, positional tabs, note and comment references, pictures and fields keep the paragraph.
- `{{}}` and `{{#}}` (empty names) are not placeholders. `TemplateData.From` lets a text value win over an image of the same name (as the classic overloads did).
- Linear time: removals are deferred and done once per parent, so 20,000 repeated rows, or 20,000 separate condition blocks in one body, fill in about a second.
- Behaviour notes: placeholder names are trimmed and a leading `#`, `/`, `?` or `^` marks a block, so classic dictionary keys with surrounding spaces or such a first character no longer match; footnote/endnote and comment references inside repeated content are copied as they are (each copy points to the same note); filled text nodes always carry `xml:space="preserve"`; text written as `{{#…}}`, `{{?…}}`, `{{^…}}` or `{{/…}}` is now template syntax; a bool value prints as "true"/"false"; encrypted output is produced in memory (no temporary file); `Fill(path, path, null)` is now ambiguous at compile time — pass a typed dictionary or `TemplateData`.

### Loading, for paginators (requests from Chuvadi.Layout)

- **Hyperlink targets on loaded runs**: runs inside `w:hyperlink` get `Run.HyperlinkUrl` from the part's relationship (body, tables, headers, footers; a `w:anchor` is appended as `#fragment`). A loaded link keeps exactly its own character style — no Hyperlink style is implied — and is written back as a link. Internal links (anchor only) come with bookmarks in Phase 8.
- **Positional tabs**: `w:ptab` loads as a run with `Run.PositionalTab` (`PositionalTab`: `Alignment` left/center/right, `RelativeTo` margin/indent, `Leader`) and text "\t"; `Paragraph.PositionalTab(...)` adds one; written as Word writes it; `DocxReader` reads it as a tab.
- **`PageSetup.SizeStated`**: false when a loaded section has no valid `w:pgSz` (Word then applies its own default size); `Size` stays non-null (A4) so nothing breaks, and no `w:pgSz` is written back for it. A loaded paper code is now kept with any preset size (it was cleared unless the size was A4).
- **Only Word packages load**: `Document.Load` and `DocxReader.Open` throw `DocxFormatException` when the main part's content type is not a Word document, template or their macro-enabled forms (e.g. a workbook renamed .docx).
- **`Document.DefaultTabStopPt`** (settings `w:defaultTabStop`, read and written; null = not stated) and `EffectiveDefaultTabStopPt` (36pt when not stated).
- Requires the canonical shared-ooxml `shared/Chuvadi.Internal/OoxmlPackage.cs` (D-36; applied on main before this release): Docs uses its `GetPart` and case-insensitive part names.

## 1.4.0 (2026-10-28)

Lists (the full numbering model and Word-compatible list labels) and sections (multiple sections, columns, per-section headers and footers, page numbering, watermarks), both read back by Document.Load.

### Sections

- **Multiple sections**: `Document.AddSectionBreak(start)` (next page, continuous, even/odd page, next column) ends the current section on the last paragraph — the current `Section` object, with its headers, footers and watermark, becomes the ended section — and returns a new section whose layout is a copy (a different first page is kept, a page-number restart is not) with headers/footers linked to the previous ones; `Document.Sections`; `Paragraph.SectionProperties`; `Document.Section` is the last section, and `Page`, `Header`, `Footer`, `FirstPageHeader`, `FirstPageFooter`, `DifferentFirstPage` are now shortcuts into it (single-section output is byte-identical to 1.3.0).
- **Section model** (`Section`, w:sectPr in schema order): page setup, start type, text columns (`SectionColumns`: count, spacing, separator line, unequal `ColumnDefinition`s), page numbering (`PageNumbering`: format, restart value, chapter style and separator), line numbers (`LineNumbering`), page borders (`PageBorders`: sides, offset from text/page, which pages, in front/behind), vertical alignment, text direction, right-to-left layout and gutter, form protection, no endnotes, document grid (`DocumentGrid`), and the title-page flag (automatic by default).
- **Headers and footers per section**: default, first page and even page (`EvenPageHeader`/`EvenPageFooter`, with `Document.DifferentOddAndEvenPages`, automatic when even-page content exists); an empty header/footer of a later section is linked to the previous one unless `LinkToPrevious = false` (written blank); headers and footers can hold tables (`HeaderFooterContent.AddTable`, `Blocks`, `Tables`).
- **Page setup**: more preset sizes (A3, A5, B5, Executive, Tabloid) and custom sizes (`PageSize.Custom`, `SetCustomSize`, Word's 22-inch limit), header/footer distance, gutter, paper code and paper trays; `WidthPt`/`HeightPt` as laid out. Document settings `MirrorMargins` and `GutterAtTop`.
- **Text watermarks**: `Section.Watermark = new TextWatermark("DRAFT")` (font, colour, opacity, diagonal/horizontal, optional size) writes Word's WordArt watermark into the section's headers — creating header parts when there is no header content, carrying the inherited header text along when the header was linked — and loads back from Word files, staying in exactly the header types (default / first / even) that carried it.
- **Document.Load reads sections**: every section's properties and its header/footer parts (each part read once; shared parts shared), first/even headers, linked headers, blank headers, header tables, page-number fields (PAGE, NUMPAGES, SECTIONPAGES — simple and complex fields load as field runs again, with their run formatting, which is now written; an unterminated field keeps its text; other fields keep their result text), text watermarks and the document page settings (even-page headers that Word keeps hidden stay hidden). A header/footer part used by several sections is loaded once and shared, and written once. A malformed header/footer or settings part loads blank instead of failing the load. Previously headers, footers and all section settings were lost on load → save. Load → save reproduces document.xml and the header/footer parts exactly for files written by Chuvadi.Docs.
- List labels are counted per header/footer of every section; lists, styles and numbering used only in later sections' headers/footers are written.
- `HeaderFooterContent.Clear()` also removes tables; `RemoveTable`. Changing `PageSetup.Size` or the custom size clears a loaded `PaperCode`; unequal columns imply `equalWidth="0"`.
- Robust against hostile section properties: absurd or zero page sizes and margins, negative distances, spacings and start values are ignored, at most six header/footer references per section, 45 columns, line-number counts up to 100 and missing header parts are tolerated.
- Behaviour notes: loaded templates now come with their header/footer content, so `doc.Header.Add(..)` appends to it (use `SetText` / `Clear` to replace); a section's `Start` describes how THAT section begins (`AddSectionBreak(start)` sets it on the new section); a new section's layout starts as a copy of the previous one; header images and other drawings are not loaded (as in the body); `printerSettings` and section change history are not kept; footnote/endnote section properties are carried verbatim until notes are modelled.

### Lists

- **Numbering model** (`Document.Numbering`, `NumberingCollection`): list definitions (`NumberingDefinition`, w:abstractNum) with nine `NumberingLevel`s, and the list instances paragraphs use (`ListInstance`, w:num) with per-level `LevelOverride`s (start override, replacement level). Levels carry start value, all 63 `NumberFormat`s (ST_NumberFormat) plus `CustomFormat` (e.g. "001, 002, 003, ..." or Tamil digits), label text with %1–%9, label alignment, restart rule, legal numbering, suffix (tab / space / nothing), linked paragraph style, indent/tab formatting, label run formatting (e.g. a bullet font or colour), picture-bullet id, template code and tentative flag. Definitions carry name, nsid, template code, multi-level type, `StyleLink` and `NumStyleLink`.
- Presets: `AddBulletList(symbols)`, `AddNumberedList(format, pattern)` (e.g. `(LowerRoman, "({0})")`), `AddOutlineList()` (1. / 1.1. / 1.1.1.), `NumberingDefinition.PerLevel(...)`; `Numbering.Restart(list, level, startAt)` gives Word's "Restart at"; instances of one definition continue each other's numbering.
- **Paragraphs**: `Paragraph.ListInstance` / `SetList(list, level)`, `Document.AddListItem(text, list, level)`, and `NumberingSuppressed` (numId 0: switches off numbering a style would apply). `AddBullet` / `AddNumbered` / `ListKind` keep working through two built-in default lists and produce byte-identical output to 1.3.0. Setting `List = ListKind.None` removes a paragraph from any list.
- **Styles**: `StyleDefinition.ListInstance` / `ListLevel` / `NumberingSuppressed` for style-linked numbering (numbered headings), replacing the verbatim numPr carry-through.
- **List labels**: `Document.GetListLabels()` / `GetListLabel(paragraph)` return what Word shows for every list paragraph (`ListLabel`: text such as "2.3." or "iv)", number, level, list, effective level, suffix and effective label formatting). Counting follows Word: per story (body incl. tables and nested tables; each header/footer), instances of one definition share counters, start overrides restart at an instance's first use, deeper levels restart after a shallower item unless `RestartAfterLevel` says otherwise, a level skipped over counts once at its start, legal numbering shows decimals, and numbering through paragraph styles and `numStyleLink` is included. Rendered formats: decimal, decimal zero, roman, letters (aa, bbb after z), ordinal, English cardinal/ordinal text, hex, Chicago, full-width, enclosed circle / parenthesis / full stop, number in dash, ideographic digits, Hindi and Thai digits and custom digit formats; other formats fall back to decimal digits in labels (they are still written and read exactly). Verified against LibreOffice for every format it renders.
- **Effective paragraph formatting** now includes a list item's level formatting (indents, number tab): below the paragraph style when the numbering comes from the style, above it when numbering is applied to the paragraph directly — as Word renders List Paragraph items.
- **Document.Load reads numbering.xml** into the model and links paragraphs and styles to their lists (previously every foreign list became a plain bullet list). Load → save reproduces numbering.xml and document.xml exactly for files written by Chuvadi.Docs. From Word files it keeps custom number formats (Word's `mc:AlternateContent` form, read and written back as Word writes it), picture bullets with their images, `w:legacy`, `numIdMacAtCleanup`, unknown number-format tokens, a level's character style, and attributes such as `w15:restartNumberingAfterBreak` and `w16cid:durableId` (declared ignorable, as Word does).
- **Level-only numbering**: a `w:numPr` with only `w:ilvl` — on a style (e.g. Heading 2 based on a numbered Heading 1) or a paragraph (`Paragraph.StyleListLevel`) — selects the level of style numbering, and is written back.
- **Only the document's own lists number paragraphs**: `AddListItem` refuses a list from another document, a removed list or a built-in default list; a paragraph or style that still refers to such a list gets no label, no list indent and no `w:numPr` on save — labels, effective formatting and the saved file always agree.
- Ids: new list and definition ids never collide or overflow (a file using ids up to int.MaxValue makes new lists take the lowest free ids); a removed definition can be added again; `NumberingDefinition.Clone` does not copy the nsid; `ListInstance.TryGetOverride` looks up an override without creating one; `Restart` follows `numStyleLink` for the level's start value.
- Robust against hostile numbering parts: duplicate ids (first wins), out-of-range levels, `numStyleLink` cycles, `int.MaxValue` start values (no overflow) and dangling ids are handled; at most 32,768 definitions and instances are read; linking paragraphs to lists is linear time.
- **Malformed parts**: a well-formedness error inside a table, list level or style that .NET's subtree readers swallowed (the part loaded partly) now throws `XmlException`, for document.xml, styles.xml and numbering.xml alike.
- Fixes: a list or style used only inside a nested table now gets its numbering part and built-in style written (nested-table paragraphs were missed when collecting what the document uses).
- Behaviour notes: a `numId` with no list in numbering.xml is dropped on load (Word shows no number for it either); loaded list paragraphs keep their style (previously a foreign list item's Normal style was changed to List Paragraph); setting `ListInstance` clears a built-in `List` kind and setting it to null leaves the paragraph without direct list membership; `Paragraph.List` reads None for numbering that comes from the style; the built-in default lists behind `AddBullet` / `AddNumbered` appear in `ListLabel.List` with ids -1 / -2 and are not part of `Document.Numbering`.

## 1.3.0 (2026-10-28)

The style model with effective (resolved) formatting, the theme carried through, and the complete table model: table/row/cell properties, merges, nested tables, table styles with conditional formats, and exact load → save round-trip.

### Tables

- **Table formatting** (`DocTable.Format`, `TableFormat`): table style + `TableLook`, width (`TableWidth.Points` / `Percent` / `Auto`), alignment, indent, fixed/autofit layout, borders incl. inside lines (`TableBorders.Grid` / `Horizontal` / `NoBorders`), default cell margins, cell spacing, shading, right-to-left, band sizes, and the accessibility caption/description.
- **Rows**: height with rule (auto / at least / exact), can't-split, repeat-as-header (now settable), row alignment, hidden, grid-before/after for ragged tables.
- **Cells**: vertical merge (`VerticalMerge.Restart` / `Continue`), width, full shading, borders incl. diagonals, margins, vertical alignment, text direction (rotated headers), no-wrap, fit-text, hide-mark; **nested tables** (`TableCell.AddTable`, `NestedTables`, ordered `Blocks`; Word's trailing paragraph is written automatically).
- **Table styles**: `StyleDefinition.TableFormat`, `RowFormat`, `CellFormat` and conditional formats per `TableRegion` (whole table, odd/even row and column bands, first/last row and column, the four corner cells) with paragraph, run, border, margin, row and cell formatting; `Styles.AddTableStyle`. Replaces the verbatim carry-through of 1.3-dev.
- **Effective table formatting**: `Document.GetEffectiveTableFormat(table)`, `GetEffectiveCellFormat(TableCellRef)` (table borders mapped onto each cell edge, style cell format, applicable regions in Word's order, direct cell formatting) and table-aware `GetEffectiveRunFormat` / `GetEffectiveParagraphFormat(…, TableCellRef)` with the table style as the lowest style level in the toggle rule. Verified against Word's built-in "Light Grid Accent 1" style (bold heading-font header with 2.25pt rule, banded rows #D3DFEE).
- **Document.Load builds structured tables** — every table/row/cell property, merges, spans, ragged rows, nested tables (text in content controls inside cells is kept) — instead of text-only grids; load → save reproduces `document.xml` exactly, tables included. Hostile tables (huge spans, rows wider than the grid) are clamped and loaded.
- **Rows and cells**: legacy horizontal merges (`TableCell.HorizontalMerge`), the widths of skipped grid columns (`TableRow.WidthBefore` / `WidthAfter`) and per-row cell spacing (`TableRow.CellSpacingPt`) are read and written.
- Rows and cells wrapped in content controls or custom XML (`w:sdt`, `w:customXml`) are loaded with their content; the wrapper itself is not kept on save.
- Fixes: `tblLayout` is now written after `tblBorders`/`shd` as CT_TblPr requires; a spanned cell's width is the sum of the columns it covers (was only the first); empty text runs (`<w:t/>`) survive load → save.
- Robust against hostile tables: loaded tables are capped at Word's 63 grid columns (extra cells beyond the cap are dropped), a huge `gridSpan` or `gridBefore` can neither widen the grid nor push later cells out, placeholder cells are created only when accessed, ragged rows stay ragged on save (missing trailing cells are not invented), and a table nested inside itself is refused (`ArgumentException` from `TableCell.AddTable`; `InvalidOperationException` at save as a last guard) instead of overflowing the stack. `GridBefore`/`GridAfter` are clamped to the row when written.
- Nested tables are anchored to the paragraph they follow, so inserting or removing paragraphs earlier in the cell no longer moves them.
- Effective formatting follows ECMA-376 §17.7.6: conditional regions apply in the order whole table, column bands, row bands, first/last row, first/last column, then the corner cells (so the first column beats the header row and `nwCell` beats both); borders apply level by level, so a region's table border overrides an earlier level's cell border. A conditional format's table properties (`TableConditionalFormat.TableFormat`: shading, alignment, indent, spacing…) are kept, written and its shading applied; table styles write every stated table property, including `tblLook` and `tblW`. A `TableCellRef` outside its table throws `ArgumentOutOfRangeException`.
- Behaviour notes: loaded tables keep exactly the borders the file states (`Borders` is false and `Format.Borders` holds them) instead of the legacy default grid; when no `tblLook` is set anywhere, Word's default look applies (`TableLook.Default`, 0x04A0: header row, first column, row banding — what Word and LibreOffice do); floating-table positioning is carried verbatim; conditional-formatting marks on cells (`cnfStyle`, a cache Word recomputes) and row-level property exceptions (`tblPrEx`) are not kept; `DocTable.GetText()` and `TableCell.GetText()` include the text of nested tables; table-style regions are written in ST_TblStyleOverrideType order (Word's order).

### Styles

- **Style model**: `Document.Styles` (`StyleCollection`) of `StyleDefinition`s — paragraph, character, table and numbering styles with id, name, aliases, basedOn, next, link, default, custom, quick-format, UI priority, hidden / semi-hidden / unhide-when-used, locked, auto-redefine, a `ParagraphFormat` and a run `TextFormat`. `AddParagraphStyle` / `AddCharacterStyle` helpers; `AddOrReplace`, `Remove`, `TryGet`, `GetDefault`.
- **Document defaults**: `Document.Defaults` (`RunFormat`, `ParagraphFormat`) replace the hard-coded Calibri 11pt; set e.g. `FontForAllScripts = "Nirmala UI"` once for a whole Indic document.
- **Custom styles in content**: `Paragraph.StyleId` (any style id; built-in ids map to `ParagraphStyle`) and character styles on runs via `Paragraph.StyledText(text, characterStyleId)` / `Run.CharacterStyleId`.
- **Effective formatting**: `Document.GetEffectiveRunFormat(paragraph, run)` and `GetEffectiveParagraphFormat(paragraph)` resolve document defaults → paragraph style chain → character style chain → direct formatting, with toggle properties combining by exclusive-or between paragraph and character styles (ECMA-376 §17.7.3), tab stops accumulating (Clear removes) and borders merging per side. Robust to basedOn cycles and missing styles. Verified against a Word-authored styles.xml (164 styles; Heading 1 resolves to Word's 14pt bold accent-1 heading font).
- **Document.Load reads styles.xml** — every style and the document defaults — and keeps custom paragraph and character style ids on content (previously unknown style ids became Normal). Load → save reproduces both `styles.xml` and `document.xml` exactly for documents written by Chuvadi.Docs.
- Built-in styles now come from the model, with the same look; headings and Title, Quote and List Paragraph are based on Normal with Next = Normal, headings keep with the next paragraph and keep their lines together (Word's behaviour), and style bold/size now also apply to complex-script text (`bCs`/`szCs`).
- **Theme carried through**: `Document.ThemeXml` holds the theme part (word/theme/theme1.xml) of a loaded document and writes it back, so theme fonts and colours survive load → save (verified: LibreOffice renders a Word-authored file in the same fonts before and after).
- **Never a dangling style reference**: built-in styles that content refers to but a loaded styles.xml lacks (Word lists only styles in use) — e.g. after adding a heading, hyperlink or list item to a loaded file — are written to the output; the document's own collection is not changed.
- Styles keep their numbering reference (`numPr`) verbatim through load → save until lists are modelled. (Table-style properties are modelled — see Tables.)
- Duplicate style ids in a loaded styles.xml: the first definition wins (linear time, robust to hostile files).
- Colour `auto` is kept as an explicit value (`ColorHex = "auto"`, also for underline colour) so it overrides an inherited colour; previously it read as "unset".
- Effective paragraph formatting: a level that sets a first-line indent replaces an inherited hanging indent (and vice versa), and explicit spacing replaces inherited auto-spacing. A paragraph referring to a non-paragraph style falls back to the default paragraph style.
- Design choice: toggles combined from the style levels replace a toggle set in the document defaults (the spec leaves this open; Word documents do not set toggles in docDefaults in practice).
- Not yet loaded: latent style information (Word regenerates it).

## 1.2.0 (2026-10-28)

Hardening for untrusted input, the complete character (run) and paragraph models, Indic/complex-script fixes, and cancellable, faster encryption.

### Fixes

- `DocxReader` text extraction no longer turns tab-stop definitions (`w:pPr/w:tabs`) into tab characters — Word documents with custom tab stops gained phantom leading tabs per stop — and ignores the style recorded in `w:pPrChange` history.
- `Document.SaveTo(Stream)` now leaves the caller's stream open (flushed, positioned at the end). Previously it disposed it, so save-to-MemoryStream-then-read failed.

### Paragraph model

- **`ParagraphFormat`** (`Paragraph.Format`, plus `ApplyFormat` / `Configure` / `Clone`) with the full paragraph-property set: alignment (now also distribute, kashida and Thai distributed), keep with next, keep lines together, page break before (`StartOnNewPage`), widow control, line-number and hyphenation suppression; space before/after (points or auto), line spacing (`LineSpacing.Multiple` / `Exactly` / `AtLeast`), contextual spacing; left/right/first-line/hanging indents and mirror indents; paragraph borders (top, left, bottom, right, between, bar) and shading; custom tab stops with alignment and leaders; outline level, bidi, font alignment, grid snapping; East Asian line-breaking toggles; and the paragraph mark's own run formatting (`MarkFormat`), which sets the height of empty paragraphs.
- Shared value types **`Shading`** (all 38 ST_Shd patterns, pattern color, fill, theme fill), **`BorderSpec`** (27 line styles, width, color, theme color, spacing, shadow, frame; Word's decorative art borders round-trip via `RawStyleToken`), **`TabStop`** and **`LineSpacing`**, reused by tables in a later phase.
- **`TextFormat.Shading`** carries full run shading; a plain fill still loads as `ShadingHex`. This closes the run-shading gap noted under the text model.
- **Heading 1–9**: `AddHeading` accepts levels 1–9 (previously 1–3) and `styles.xml` defines Heading 4–9 with outline levels.
- `Paragraph.Alignment` is now a shortcut for `Format.Alignment` (Left means inherit); existing code and output are unchanged.
- Robust against odd or hostile input: non-finite, underflowing or absurd measurements are ignored on load (never thrown), border width/spacing are clamped to the schema ranges, out-of-range outline levels and non-token `textAlignment` values are ignored. Values set through the API that cannot be written (undefined enum values, NaN measurements, a non-token `RawStyleToken`) fail clearly at save with `ArgumentException`/`ArgumentOutOfRangeException`.
- **Behaviour changes for loaded documents:** `jc="distribute"` now loads as `ParagraphAlignment.Distribute` (was `Justify`); a run's tabs and plain line breaks load inside its text (`\t`, `\n`) rather than as separate `IsTab` / `Break == Line` runs. An encrypted file opened with NO password now reports `DocxPasswordRequiredException` even when its spin count exceeds `MaxSpinCount` (the password check runs first).
- **Document.Load** reads every paragraph property, including Word's `w:start`/`w:end` indents and borders; tracked previous properties never override. A run (`w:r`) now loads as ONE `Run` whose text carries `\t` / `\n` for its tabs and line breaks, so a load → save round-trip reproduces `document.xml` exactly, paragraph properties included. Page, column and text-wrapping breaks remain explicit `Break` runs.

### Text model (run formatting, scripts, breaks)

- **Complete run formatting on `TextFormat`**: four font slots (`AsciiFont`, `HighAnsiFont`, `EastAsiaFont`, `ComplexScriptFont`) plus `FontForAllScripts`, theme fonts per slot and `FontHint`; complex-script `BoldComplexScript`, `ItalicComplexScript`, `SizeComplexScriptPt`, `ComplexScript`, `RightToLeft`; `Language` / `EastAsiaLanguage` / `ComplexScriptLanguage`; `UnderlineStyle` (all 18 styles) and `UnderlineColorHex`; `DoubleStrikethrough`, `Caps`, `SmallCaps`, `Hidden`, `Outline`, `Shadow`, `Emboss`, `Imprint`, `NoProof`; `VerticalPosition` (superscript/subscript), `BaselineShiftPt`, `CharacterSpacingPt`, `HorizontalScalePercent`, `KerningMinSizePt`; `ThemeColor` with tint/shade; `ShadingHex`. New toggles are tri-state (`bool?`) so they can switch an inherited effect off.
- **Indic / complex-script fix**: `Font` only ever filled the Latin slots, so Tamil, Devanagari or Malayalam text ignored it, and bold/size didn't apply to those scripts. `FontForAllScripts` and `ComplexScriptFont` set the slot those scripts use, and with `MirrorToComplexScript` (default on) `Bold`, `Italic` and `SizePt` also write `bCs`, `iCs` and `szCs`, as Word's toolbar does. Document defaults now include `szCs`, so complex-script text defaults to 11pt like Latin text instead of Word's 10pt fallback.
- **Breaks and tabs**: `Paragraph.Break(BreakType)` — line, page, column, and text-wrapping breaks that clear floating objects left/right/both — plus `LineBreak()` and `Tab()`. `\n`, `\r\n` and `\r` in text are written as `w:br`, and `\t` as `w:tab` (previously they landed inside `w:t` and rendered as spaces); the stored run text is unchanged.
- **Templates**: line feeds and tabs inside a FILLED value become `w:br` / `w:tab` in the same run, keeping its formatting. Untouched template text is never altered.
- **Formatted hyperlinks**: `Paragraph.Hyperlink(text, url, TextFormat)` layers formatting over the Hyperlink character style.
- **Document.Load reads every run property** through the same mapping the writer uses, and loads breaks, tabs, non-breaking and soft hyphens as runs; text inside text boxes is kept (flattened). Loaded formats carry complex-script properties exactly as stated (`MirrorToComplexScript = false`), so load → save reproduces `document.xml` exactly. Tracked previous paragraph properties (`w:pPrChange`) no longer override current ones on load, and `numId 0` is no longer treated as a list.
- `TextFormat.ExplicitlyOff` (`RunToggles`) carries bold/italic/strikethrough written as explicitly off (`w:val="0"`), so a run that cancels a style's bold round-trips; `highlight="none"` is kept likewise. Known gap until the shading model lands: run shading keeps only its fill color.
- Text boxes stored as `mc:AlternateContent` are read once (the `mc:Fallback` copy is skipped) and moved-away / deleted content (`w:moveFrom`, `w:del`) is no longer shown — by both `Document.Load` and `DocxReader`. Previously text-box text appeared twice.
- **Schema order fix**: `w:highlight` is now written before `w:u`, as CT_RPr requires (previously reversed).
- `DocxReader` text extraction maps non-breaking and soft hyphens to U+2011 and U+00AD.

### Shared crypto (shared/Chuvadi.Internal — additive)

- Key derivation observes a `CancellationToken` (checked every 4,096 rounds, ~10 ms) and the decryptor takes an optional spin-count cap, checked after EncryptionInfo is parsed and before any derivation. Chuvadi.Docs now passes `MaxSpinCount` and the caller's token straight through: cancelling `DocxReader.Open`, `Document.Load` or `DocxTemplate.Fill` on an encrypted file stops key derivation too. Existing internal signatures are unchanged (Sheets is unaffected until it opts in).
- The iterated hash is computed once per open/save instead of three times (the verifier keys and key-encryption key share it): opening an encrypted file is ~3.4× faster (1,000,000 spins: 2.4 s → 0.7 s), with byte-identical results. Cross-checked with msoffcrypto-tool (HMAC verified).

### Hardening for untrusted input

- **Resource limits** on `DocxReaderOptions`, applied by `DocxReader.Open`, `Document.Load` and `DocxTemplate.Fill`: `MaxEntries` (10,000), `MaxTotalUncompressedBytes` (1 GiB), `MaxCompressionRatio` (1,000:1 above `CompressionRatioThresholdBytes`, 1 MiB), `MaxXmlDepth` (256) and `MaxSpinCount` (500,000). Package limits are checked from the zip central directory before any part is inflated; the declared sizes are a hard ceiling because the runtime never inflates an entry past them. The spin count is read from EncryptionInfo before key derivation starts. Every limit is nullable; `DocxReaderOptions.CreateUnrestricted()` disables them all.
- **`DocxSecurityLimitException`** (derives from `DocxFormatException`) reports `Limit`, `Actual`, `Allowed` and `PartName`. `DocxFormatException` is no longer sealed.
- **Active-content detection** (detect only, never execute or fetch): `DocxReader.HasMacros`, `ContainsVbaProject`, `IsMacroEnabledPackage`, `MainPartContentType`, and `GetActiveContent()` returning `DocxActiveContent` — ActiveX controls, embedded OLE objects, altChunks, DDE/DDEAUTO fields (including instructions split across runs), remote attached templates, other fetch-on-render external resources, and every external reference verbatim.
- **Cancellation**: `CancellationToken` overloads on `DocxReader.Open` (path and stream), `Paragraphs`, `Tables`, `ExtractText`, `Images`, `SaveImages`, `GetActiveContent`, and new `Document.Load(path|stream, password, options, cancellationToken)` overloads. Checked on every XML node and every decompression buffer fill; cancellation latency measured at under a millisecond.
- `MaxPackageBytes` (1 GiB) bounds the input file/stream itself before it is buffered or decrypted.
- **Behaviour change:** a `MaxPartBytes` breach now throws `DocxSecurityLimitException` (`Limit = PartBytes`) instead of `InvalidDataException`, from every reader path, and also caps embedded media read by `Images()`; `Document.Load` no longer swallows it while collecting images.
- `DocxTemplate.Fill` gains an overload taking `DocxReaderOptions` and a `CancellationToken`; the existing overloads apply the default limits. A cancelled fill writes no output.
- `DocxReader.Open(stream)` takes ownership of the stream on every path (disposed with the reader, or when opening fails), accepts non-seekable streams (buffered, bounded), and opening a file path that turns out to be encrypted no longer leaks the file handle.
- Fix (pre-existing): an empty `<wp:inline/>`/`<wp:anchor/>` made `Images()` and `Document.Load` loop forever.
- DDE detection scans every WordprocessingML part (comments, glossary…), and a linked (external) OLE object is reported as an external resource, not an embedded object.
- README: fixed an image example that called the internal `AddBlock`.

## 1.1.0 (2026-06-12)

Image support — read, write, and templates.

- **Write**: insert inline and floating images anywhere a run can go — `Document.AddImage`, `Paragraph.Image`, `TableCell.SetImage`/`AddImage`. Full DrawingML emission (`wp:inline` and `wp:anchor`) with every floating option exposed: horizontal/vertical anchors (page/margin/column/character/line/paragraph and the four margin variants), named alignment or point offsets, all five wrap modes (square, tight, through, top-and-bottom, none), behind/in-front-of text, overlap and anchor locking, z-order, and wrap padding.
- **Auto-sizing**: `ImageSpec.FromFile`/`FromBytes` read pixel dimensions and DPI from PNG, JPEG, BMP, GIF, and TIFF headers (pure BCL, no System.Drawing) to compute display size in points; `ScaleToWidth`/`ScaleToHeight` preserve aspect ratio. Explicit sizing via `Inline`/`Float` for any format including EMF/WMF.
- **Read**: `DocxReader.Images()` returns every image (body, headers, footers) with bytes, content type, display size, placement, floating position, and — for images in tables — table/row/column location. `DocxReader.SaveImages(folder)` extracts them to disk. `Document.Load(...).Images` exposes the same on the editable model. This metadata is the input the planned PDF pipeline consumes.
- **Templates**: `DocxTemplate.Fill` gains an `imageValues` overload with two mechanisms — *text-to-image* (`{{Key}}` becomes an inline/floating image in place) and *replace-by-alt-text* (an existing template image whose alt text matches a key has its bytes swapped, keeping the template's position and size). Media parts, relationships, and content-type entries are injected automatically; everything else is still copied byte-for-byte.
- **Reader fix**: `[Content_Types].xml` `<Default Extension=...>` mappings are now honored when resolving parts, not just `<Override>` entries. This lets the reader open image (and other) media parts in documents authored by Word, which declare media via Default extension rules.

Cross-validated against python-docx (inline shape dimensions read back exactly; media bytes verified by SHA-256) and msoffcrypto-tool (encrypted documents containing images decrypt and round-trip).

## 1.0.0 (2026-06-11)

Initial release.

- **Writer**: paragraphs with run formatting (bold, italic, underline, strikethrough, font, size, color, highlight); styles (Title, Heading 1–3, Quote, Normal); alignment; bulleted/numbered lists with nesting; hyperlinks; page breaks; tables (borders, header rows, shading, column widths, column spans); headers/footers with PAGE/NUMPAGES fields and different-first-page; page setup (A4/Letter/Legal, portrait/landscape, margins).
- **Templates**: `DocxTemplate.Fill` replaces `{{Placeholders}}` in body, headers, footers, footnotes, endnotes while preserving everything else in the file byte-for-byte; handles placeholders split across runs; supports encrypted input and encrypted output.
- **Reader**: `DocxReader` (paragraph stream with styles, table grids, full-text extraction) with `MaxPartBytes` decompression cap; `Document.Load` builds an editable model with basic formatting.
- **Security**: OOXML Agile Encryption read/write (AES-256-CBC, iterated SHA-512 KDF, HMAC-SHA512 verified on decrypt) via the shared Chuvadi crypto internals; restrict-editing protection (`documentProtection`, iterated SHA-512 password hash); DTD processing prohibited everywhere.
- Pure BCL; zero NuGet dependencies; single-assembly DLL.

Cross-validated against python-docx and msoffcrypto-tool.
